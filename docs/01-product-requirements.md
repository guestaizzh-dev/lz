- **付费会员**：普通用户能力 + 当前有效套餐定义的权益，权益不能仅靠前端隐藏或展示来控制。
- **老师/助教**：后台授予；处理指定课程作业、指定讨论区、自己的问答和预约，不能查看无关用户财务信息。
- **运营/审核/客服/财务**：不同管理角色；内容发布、举报处理、售后审批、结算权限拆分。
- **超级管理员**：角色、基础配置、支付渠道和运营规则管理；高风险操作写审计记录。

每个后台接口均检验角色和资源归属。菜单不可见不能替代 API 权限检查。

## 6. 模块需求和验收

### 6.1 身份、搜索、消息、个人中心

**R1**

- 手机号验证码注册/登录；验证码次数、有效期、频率由服务端校验，退出撤销当前会话。
- 首次使用自主选择兴趣标签；后续可修改，不强制游客填写。
- 昵称头像、学习进度、订单、会员、收藏、私人笔记、日志、积分、消息、售后入口。
- 站内综合搜索，分文章、课程、名师、商品、社区、活动展示；只返回用户可见或可购买的资源。
- 站内消息承载订单、预约、课程、审核结果；用户开启推送后同步关键提醒。不开推送不妨碍使用。
- 设置含隐私说明、服务协议、权限管理说明、注销、退出、版本检查、缓存清理、反馈及客服。
- 用户拒绝非必要权限后仍可浏览；相册、摄像头、麦克风等按实际操作请求。

**R2**：微信登录、Apple 登录及账号安全绑定；行为加权推荐；消息偏好细化。增加第三方登录前，必须处理相应平台的登录要求和重复账号合并。

**验收**：验证码不可重复用于多个会话；过期/冻结账号不能访问私人 API；修改兴趣即影响推荐；跨账号无法读取订单、笔记或日志；注销有确认和会话撤销，并按数据保留策略处理未结订单。

### 6.2 文章与经典内容

**R1**

- 分类：经典原文、名师解读、实践心得、道学常识；标签、作者、相关名师/课程/商品可配置。
- 图文、音频、视频内容；经典记录来源/版本，译注注明作者和授权信息。音视频使用受控媒体绑定，失败不得中断文字阅读，字号/高亮变化不重置播放；下架、修订或权益失效需撤销旧播放凭证。
- 文章、名师、商品来源证据支持私有原件、人工核查、有效期和新版本；公开仅展示允许的摘要。已绑定来源声明重新发布前须有有效已审版本；样例不因点审核变成真实核验。实现与正式材料边界见[64](64-content-linkage-and-interactions.md)。
- 状态：草稿 → 待审核 → 已发布 → 下架；拒绝后可修订重新审核；只有已发布可供用户阅读。
- 点赞、收藏、评论、举报、分享；阅读历史和访问量去重规则由后端统一。
- 私人文章笔记可绑定段落 ID；修改文章保留稳定段落标识，删除段落的笔记仍能查看原引用片段。
- 会员文章正文鉴权；预览内容单独定义，禁止在未授权响应中发送完整正文。

**R2**：文本范围标注；整理并导出私人笔记；后台古籍/水墨模板；系统分享、微信好友和平台支持的朋友圈分享。

**验收**：下架内容不可通过旧 URL 读取正文；用户 A 看不到 B 的笔记；修改正文不会悄悄改变笔记引用；媒体加载失败不阻止文字阅读。

### 6.3 名师、问答与咨询

**R1**

- 档案含简介、研究方向、传承背景（经审核）、授课方向、媒体、课程、直播和线下活动。
- 用户提交问题；老师答复可标记公开/仅提问者可见；公开答复须经过审核。
- 一对一预约以可售时段为库存；价格、时长、服务方式、提前预约时间由后台配置。
- 支付前短暂锁定时段；支付失败/超时释放；支付成功确认预约；老师拒绝或取消进入退款处理。
- 预约入口与商城服务商品指向同一服务和库存，禁止各维护一份可售时段。
- R1 咨询通过预约信息约定电话、外部会议或现场交付；联系信息仅预约双方及授权客服可见。

**R2**：App 内实时一对一咨询；会员优先预约和指定问答额度；签名书籍/文创作为实际可履约权益配置。

**验收**：多人抢同一时段最多一单确认成功；支付回调迟到有明确退款补偿路径；取消与退款结果通知双方；其他老师不能查看不属于自己的预约。

### 6.4 课程、学习与实践

**R1**

- 经典研习、实践修行、生活应用、少儿启蒙四类；视频、音频、直播、训练营、线下课程五种交付方式。
- 课程详情含老师、介绍、章节、价格、可试听章节、会员权益、有效期、退课规则。
- 音视频课按章学习，续播、倍速、进度同步；服务端记录学习，不采用客户端上报的“已购买”或“会员”标记授权。
- 课程默认单次购买长期访问已购版本，除明确售前披露的有效期课程；下架停止新购，不自动取消已购访问。
- 直播课绑定直播场次；训练营绑定开营批次、期限、章节、助教和课程讨论区；线下课绑定活动/预约库存。
- 作业支持文本与图片；老师点评；修行打卡支持日志、图片、日期，连续天数按业务时区计算。
- 购买/有效会员权益自动开放相应课程讨论区，不靠展示群码代替课程访问授权。
- 学习档案包含已购、会员可学、最近学习、完成章节、作业与打卡；课程完成规则按必修章节配置。

**R2**：受控离线音视频缓存及到期校验；作业音视频附件；更丰富的训练营进度、阶段提醒与点评；优惠券、拼团、单层课程推广分销。

**验收**：未购买者只能访问试听；过期会员不能访问会员独占章节；已有独立购课权不随会员过期而失效；播放进度断网重试不产生重复学习事件；已购课程下架仍按交付规则可学，撤销内容有补偿流程。

### 6.5 直播

**R1**

- 文化讲解、答疑、实践教学、会员专属、线下活动同步五类；公开/购课/会员准入由服务端判定。
- 直播状态：预告 → 准备 → 直播中 → 已结束 → 回放就绪，取消独立状态；真实状态以服务商回调与后台纠正为准。
- 预约、站内提醒、允许的系统推送；断线重连、播放失败提示、结束状态和审核后回放。
- 后台为授权主播生成直播会话；按用户最新决定使用ZEGO RTC，R1当前采用指定管理员桌面官方SDK开播台，用户App受控观看。普通老师独立开播入口与双端原生兼容仍需完善/验收；不以OBS/CDN流替代RTC。
- 房间评论/弹幕、管理员禁言/删除、举报；课程/商品/活动卡片和会员开通入口。
- 回放需独立审核并复用直播/课程权限，不能暴露无鉴权永久地址。

**R2**：老师 App 内开播；连麦申请和老师审批；主持人关闭麦克风/移出；投票问卷；虚拟礼物打赏；直播限时营销。

**验收**：未经授权获取不到可用会员播放凭证；主播密钥不返回给普通用户；重复开播/结束回调不破坏状态；弱网有可恢复路径；直播间删除/禁言即时生效；回放权限与直播权益一致。

### 6.6 论坛、课程讨论与内容治理

**R1**

- 六个分区：经典探讨、实践分享、养生交流、生活应用、名师问答、活动召集。
- 图文帖、话题、回复、点赞、收藏、精华和运营置顶；可引用经典和平台文章。
- 公共发帖先审后发；评论自动检查，高风险进入人工审核；老师点评不免除审核。
- 帖子/评论支持举报；管理员可驳回、隐藏、删除、禁言、封禁，记录理由和操作人。
- 用户可拉黑其他用户；被拉黑用户内容从该用户列表隐藏并限制直接互动。
- 课程讨论区与公共论坛共用内容能力，但访问范围受课程/会员权益限制。
- 平台选用用户内容作课程案例时记录授权，不默认把私人日志、笔记公开。

**R2**：音视频帖、主题活动/征文、品质参与成长评价、运营精选内容流、会员置顶申请（须审核且不能覆盖治理规则）。

**验收**：未审核帖子不能通过详情接口公开访问；课程讨论对无权限用户不泄露正文；举报可追踪处理状态；被封禁用户不能换入口继续发帖；误删有管理员恢复或申诉处理机制。

### 6.7 商城与履约

**R1**

- 分类：经典典籍、文创、养生用品、修行工具、线下服务；商品须有规格、价格、库存、交付方式、文化背景、售后规则。
- 实物支持多 SKU、购物车、地址、运费模板、订单、支付、发货、物流单号、签收和退款/退货换货申请。
- 同一实物订单可合并多个 SKU；数字资料和预约服务独立下单；订单提交保存价格、商品名、规格、地址快照。
- 数字资料支付后创建领取权益，访问地址短期签名；服务通过统一预约/活动系统交付。
- 库存按“可售、预占、已售”处理；15 分钟未付款默认关闭并释放，具体时长允许后台配置。
- 商品详情含文化溯源文字/图片及证据来源；不默认所有营销描述真实。
- 支持人工推荐、新品、热销和课程配套商品；会员折扣以服务端有效权益计算。
- R1 物流采用后台录入承运商/单号和用户跳转查询；订单状态不得用虚构物流轨迹推进。

**R2**：物流查询接口、优先物流选项（受地址及服务覆盖约束）、秒杀/满减、限量商品、组合推荐和数字资料版本更新。

**验收**：并发购买不超卖；支付金额不同于订单应收时拒绝确认；未支付不能领取资料；退款后访问权益按退款范围撤销；发货后修改个人地址不改变订单收货快照；部分退款不重复释放整单库存。

### 6.8 会员、成长和积分

**R1**

- 三个付费套餐层级：入门、进阶、至尊；月/季/年有效期，初始价格与权益见第3.1节，正式启用时后台和支付渠道产品映射必须一致。
- R1 使用手动续费，不把“订阅”默认解释为自动扣款。App 商店购买产品类型以技术文档和平台规则落实。
- 一个用户同一时间一个有效付费层级；同套餐续费从现有到期日延长；无有效套餐从生效时间计算。
- R1 不做自动补差升级：跨层级购买在原套餐到期后生效，售前显示明确生效日期；后台补偿授权需记录原因。
- 权益类型：指定课程/文章、课程折扣、商品折扣、运费权益、问答额度、活动优惠及报名优先；一切需有可兑现配置。
- 到期停止会员独享访问和未产生订单的优惠，不撤销会员有效期间独立支付取得的课程、商品及已确认预约。
- 成长值单向累计，用于社区称号，不自动变成付费会员；通过审核的参与、学习和打卡积累，日上限防刷。
- 积分独立账本：获取、冻结、消费、退款退回、到期/调整有来源和幂等键；默认不提现、不转让。
- 积分获取以订单结算、有效打卡和审核通过内容为准；退款冲回对应奖励，余额不足记录待抵扣额，不篡改历史流水。
- R1 积分兑换优惠券；兑换实物、咨询时长放入 R2，并复用真实库存和预约交付。

**R2**：自动续费产品、明确升级/降级规则、积分商品/咨询兑换、有限免费/公益套餐；会员优先连麦等依赖功能上线后才允许售卖相应权益。

**验收**：服务端时间决定过期；重复支付通知只延长一次；积分不能重复发放/消费；会员优惠退货后按实付退款，不按原价退款；套餐修改不默默减少用户已购版本权益。

### 6.9 活动与线下服务

**R1**

**R2**：多票种、候补名单、更丰富的研学安排和直播活动联动。

**验收**：核销码不能由其他活动工作人员越权核销；重复核销幂等；取消活动停止新增报名；退款与退票库存一致。

### 6.10 营销、分销与合作方结算

**R1**：人工推荐、会员折扣、课程试听、来源标记、合作协议比例、财务报表和后台人工结算。记录原始支付渠道、手续费、退款、合作方应计金额。

## 7. 统一订单、支付与退款契约

### 7.1 金额和订单

- 价格、折扣、库存、权益全部由服务端重新计算；金额存整数分，币种首期 CNY；商店本地化价格另存渠道/币种，不强行按 CNY 收据核对。
- 统一订单头 + 业务订单项/履约记录。类型：课程、实物、数字资料、会员、咨询、活动、礼物余额。
- 商业状态与支付状态分开，禁止用单一字段混淆“已支付”和“已发货”。
- 订单：待支付 → 已支付 → 履约中 → 已完成；未支付可关闭；退款使用独立申请及金额字段，支持部分退款。
- 支付尝试：已创建 → 待确认 → 成功/失败/关闭；一个订单可以多次尝试，但最多一次有效收款。
- 同订单跨渠道的重复成功付款必须记录为异常收款并启动退款/人工处理，不重复授权、不丢弃财务事实。

### 7.2 支付确认

- 客户端支付返回只触发查询，不是最终收款依据；按渠道使用服务端验签回调、主动查单或商店交易验证。
- 验证商户/应用、订单、产品、金额/币种、真实渠道交易 ID；唯一约束保证回调幂等。
- 在事务中确认支付并授予权益/确认库存，副作用通过可靠任务发送；支付已成功不能因推送失败回滚。
- 超时关单前查单；过期订单收到成功支付时重新验证可履约性，不能履约则退款并通知。
- 每日对账处理漏单、退款不一致和异常交易；保存必要原始渠道记录，不在日志输出密钥/完整个人资料。

### 7.3 退款

- 申请 → 待审核 → 已拒绝/退款中 → 已退款/退款失败；失败可重试，不等于已退款。
- 默认产品规则：数字课程首次获得授权后 7 天内且未开始付费章节可申请；实物按商品披露的退换规则；咨询/活动按服务开始前的取消截止规则；会员误购在未消耗权益时进入人工审核。以上为内部业务默认，不能覆盖适用法律/渠道规则要求。
- 商店内购退款由相应商店渠道处理；后台不伪造可直接退回的能力；交易撤销通知触发权益重算。
- 退款成功才冲回收入/佣金、撤销对应权益或释放适用库存；部分退款按退款明细处理。
