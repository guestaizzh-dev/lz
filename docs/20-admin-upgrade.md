## 安全与数据流程

服务端每次请求从数据库重新求有效权限，持久策略只能缩小现有角色权限上限；空策略表示无权限，未知后台路由拒绝访问。ADMIN保留全部能力，ADMIN/USER策略不能被运营页面改写。现有角色检查、课程/内容归属、Origin/CSRF和会话校验继续执行。权限控制覆盖直接访问接口、通用数据编辑器和已签发的后台私有图片链接；前端隐藏按钮只是配合服务端控制。

通用数据编辑不能绕过账号冻结、活动审核、课程发布/报价、交易、授权和账本流程。文章评论与论坛评论严格分开查询/审核；举报队列按目标模块过滤，处置还要校验该目标的审核权限。账户身份/冻结、授权、配置、审核等关键变更与业务审计同事务；额外的请求日志写入失败只记录服务错误，不将已提交业务伪装成失败。

新增代码分别集中在 `admin-permissions.ts`、`admin-management.ts`、`system-config.ts`、`admin-audit.ts`、`events-admin.ts`，沿用NestJS注入、已有数据库事务与Pro后台服务调用；未引入第二套后台框架。

已应用两个手写增量迁移：

- `20261009190000_admin_permission_policies`：一次性初始化角色策略，增加审计查询索引。
- `20261009200000_admin_role_baselines`：将已有非USER角色登记为可追溯、可撤销的授权记录，保留现有权限并写入基线审计。引导管理员改为通过角色授权事实建立，遵循数据库触发器。

本轮未重建测试库或新增业务表。当前150表、144目标实体查询、**41类完整通用CRUD、0类受限编辑、103类受控流程**；`app_user`、`event`、`sale_offer`收归专用流程。手写SQL约束/触发器继续是权威来源，禁止使用db push/未审查自动diff替代迁移。
