## 3. 本次确认的主要缺口

### P1：营期报名与普通购课不能并存，复报名受限

证据：`services/api/prisma/schema.prisma`中Enrollment唯一键为`[userId, courseId]`，只有一个cohortId；`services/api/src/cohorts.ts`报名检查已有记录并返回409，要求联系书院安排。独立购课者不能再报名同课程营期，参加过另一营期者也被拒绝。当前保护避免覆盖原课程权益，但缺少可完成安排的专用后台流程。

改进：为营期建立独立报名与学习上下文，保留既有购课授权、订单及学习历史。不能仅删除唯一约束或覆盖Enrollment。普通课程与不同营期须明确选择和显示归属，取消/结营只影响对应来源。

### P1：营期学习进度与成果尚无独立归属

证据：StudyProgress唯一键为`[userId, lessonId]`，CourseCertificate为`[userId, releaseId]`，无营期维度。`learning.ts`仍走整体课程访问与进度。

改进：与营期报名一并定义学习上下文，确保重报、并行学习、不同课程版本不串进度；完成记录和教学反馈归属清晰，原购课成果保留。此项是架构及功能缺口，不是已证明的越权漏洞。

### P1：分日解锁、营期助教、作业和打卡没有实现闭环

证据：CourseCohort无章节解锁配置；`learning.ts`目录、正文和进度未判断营期章节开放时间。`teaching.ts`普通教学人员/作业范围使用cohortId为空，营期提交被拒绝；`practices.ts`明确拒绝营期任务。后台营期页目前主要是创建、开放和名单。

改进：先统一服务端访问规则，再接App目录与播放器；目录、正文、媒体票据签发/读取、学习事件均须检查开放时间。补营期教学人员、专属任务、退回修订、点评、图片归属再次校验及持久通知，不能只增加页面按钮或放开通用接口。

### P1：营期延期/结束调整与付费服务仍缺业务流程

证据：`cohorts.ts`仅建立、状态、报名、取消、名单等接口。服务/活动的A01延期实现不适用于营期。免费报名不经过正式交易，不能视为付费服务完成。

改进：营期延期保留原新安排及原因，同步章节排程/任务截止，记录学员确认、退出和补偿事实；通知可靠送达。付费预约沿已有交易/权益与容量流程续办，不再另建账本。

### P1：现场核销、财务及正式运行尚未闭环

证据：`bookings.ts`目前是运营逐人checkin，在已检查调用范围内未找到EventStaff实际委派流程；O阶段分成/对账/结算/告警恢复任务仍待执行。建表不算功能完成。

改进：在已有签到基础上补活动范围内人员委派、凭证与撤销审计，完整结算/积分按前置任务实现。正式短信、云媒体、真实渠道、双端原生和实际履约证据依26恢复条件验收。

### P2：推荐缺少购买记录，会话恢复仍未实现

证据：`discovery.ts`推荐权重来源为用户标签、ReadingEvent、Reaction LIKE、Favorite，未包含有效购买/退款信号；原文P072明确包含购买记录。`apps/mobile/lib/session.ts`会话当前仅在内存保存。

改进：推荐接有效购买及撤销来源，保留发布/可见性过滤，避免退款后错误强化信号；会话用既定平台安全存储与刷新/撤销规则完成持久恢复，不能以普通Storage替代正式安全要求。
