# A03：训练营分日章节排程与解锁

记录日期：2026-10-12（沿用本批证据目录日期；验证日志含实际执行时间）。本子流程实现与本地验证完成；完整A03、原始需求CO05仍未完成商用验收。

## 交付行为

运营在官方Ant Design Pro营期管理中打开“章节安排”，按固定课程版本逐章填写开营第几天开放。第1天为开营时刻，第2天为开营24小时后；同日可开放多章，开放日按课程顺序不得倒退，所有章节须早于结营。表单实时显示北京时间，保存须填写审计说明。

新营期默认全部第1天开放。首次开放报名永久冻结章节安排；关闭或重新开放报名都不能重新编辑，避免已报名用户的既定学习安排被改写。保存与报名状态变更共用营期行锁和expectedVersion，发生并发修改返回409，界面保留表单并提供“重新读取”。该按钮会替换尚未保存的内容，错误提示对此说明。

App营期详情在报名之前显示各章名称、开放日和北京时间，正文不随售前安排公开。学习目录显示“待开放/已开放”及时间；点击锁定章节弹出具体开放时间，已报名用户不再收到购买权限提示。到开放时刻可刷新目录继续学习。保留原书院版式、宋体标题与留白，没有重新设计配色和布局。

服务端在营期目录、正文读取、媒体签发、既有媒体票据读取、付费开始记录和学习进度事务中使用同一排程检查。营期试听章同样按排程开放，不能借普通购课或会员权益绕过。普通课程不带cohortId时继续独立使用；各期学习进度仍不互相复制。未到开放日无法写入学习事件，也不能提前生成完整营期的研习完成记录。历史已生成的记录按既有规则保留。

## 数据与接口

新增一张专用流程表，不加入通用CRUD：

| 表/字段 | 类型及规则 | 用途 |
| --- | --- | --- |
| CohortLessonSchedule.id | text主键，数据库生成UUID | 单章安排身份 |
| cohortId、courseId、releaseId | 非空text；复合外键对应CourseCohort的同一期/课程/版本 | 固定本期教学版本 |
| lessonId | 非空text；与releaseId复合外键对应Lesson；cohortId/lessonId唯一 | 不接受其他版本或重复章节 |
| opensOnDay | 非空整数，默认1，范围1—3660；开放时刻须早于结营 | 由开营时刻按24小时递增计算 |
| CourseCohort.scheduleFrozenAt | 可空timestamptz；第一次离开草稿冻结，此后不得改写或清空 | 公布后安排不可变 |

数据库初始化新营期的全部章节安排；保护触发器拒绝冻结后增删改、安排身份替换及营期外的开放日。删除整个营期时可级联删除排程，但业务没有通用营期删除入口，既有报名外键也保护相关事实。章节完整性和顺序由专用事务验证，首次开放报名再次检查全部章节。

第31迁移：[20261012140000_cohort_lesson_schedule](../services/api/prisma/migrations/20261012140000_cohort_lesson_schedule/migration.sql)。在一个事务中为历史营期补全部第1天开放，已非草稿的营期补冻结时间；不给历史学习新增等待期，不改写普通授权、进度或交易。SQL与Prisma模型共同记录结构，禁止db push替代此迁移。

- `GET /admin/cohorts/:id/schedule`：读取固定章节与已保存开放日，使用courses.read及现有角色上限；只读审核角色可以查看。
- `POST /admin/cohorts/:id/schedule`：完整保存本期安排，使用courses.write，要求expectedVersion、逐章lessonId/opensOnDay、reason。
- `GET /cohorts/:id`：售前lessonSchedule只有名称、格式、顺序和开放安排。
- `GET /learning/courses/:id?cohortId=...`：目录增加opensAt、opensOnDay、lockedReason；accessible由权限、版本交付状态及章节时间共同决定。
- 既有正文、媒体和进度路由保持不变，显式营期上下文统一验证。
