# A04/A06：单次拒约与服务争议退款

2026-10-13。续办50后的个人预约拒绝、超过取消截止或已经参加后的核查与协商退款。当前子流程实现及本地验证完成，完整M04仍进行中。

## 业务与交互

- 负责老师或授权运营可拒绝未来的单次预约，须填写具体原因并提交当前版本。免费预约取消后一次释放席位；已付款预约立即暂停联系与履约，自动全额原路退款，渠道确认成功后才释放席位。原时段保持开放，不误取消其他学员或整个时段。
- 学员可从原订单申请服务核查，沿用原因弹窗。原报名、签到和购买快照保留，核查期间暂停继续参加，席位仍占用。同请求重复提交返回原记录，其他账号不能查看或操作。
- 财务核查已参加人数、原安排、已付金额及退出范围，提出整数分金额与扣除依据。后台审批只产生待确认方案，未得到学员确认不得发起退款。
- App显示拟退回金额、保留金额及整单退出范围，弹窗确认后才原路退款。拒绝方案或财务驳回，恢复原CONFIRMED或COMPLETED状态，不丢失签到、不延长取消期限；仍有异议可重新申请。
- 已确认方案的金额、评估快照、付款来源、渠道请求号与确认时间由数据库触发器保护。过期版本拒绝；同意/拒绝重试幂等。老师权限不包含财务审批。
- 渠道失败时保留暂停状态、名额和原申请，使用原持久任务与财务重试。可信退款成功才冲回实际退款金额、终止剩余服务并一次释放原库存，已有参加事实保留。
- 书院取消安排时，尚未接受的协商方案升级为全额补偿：当前扣除金额归零，原方案另存历史。已接受部分退款时保留原确认方案；该退款成功后创建剩余实付补退，累计不超过原付款，不重复释放席位。

保留书院现有米白、墨青、宋体标题与留白，不改导航或重排页面。App复用ComposeSheet及确认弹窗；Pro复用官方模板订单抽屉与服务工作台，只展示当前合法动作。金额统一人民币、时间统一北京时间。

## 数据与接口

复用Appointment、EventRegistration、Refund/RefundItem、RefundTransaction、TradeOrder及原预收账本，无新增表或业务模型。第38迁移`20261013030000_booking_refund_consent`新增协商退款状态/本人同意约束、已接受方案不可变触发器及暂停预约索引，兼容既有会员退款同意。

新增本人接口：

- `POST /commerce/booking-orders/:id/dispute`
- `POST /commerce/booking-orders/:orderId/refunds/:id/decision`

拒约入口：`POST /admin/services/appointments/:id/reject`及`/admin/teaching/appointments/:id/reject`。复用所属老师核查及courses.write/teaching.write权限；退款方案沿用受finance权限保护的原review接口。通知和审计同事务保存，不增加平行退款协议。
