## 2. 用户实际体验

- 升级后首次登录一次；后续 App 关闭再打开，在会话有效且未撤销时恢复登录。服务器仍核验冻结、注销、到期和撤销。
- 断网也能退出。普通 Storage 只存非秘密的退出标记；登录令牌和学习队列使用原生安全存储。删除安全记录失败时，退出标记阻止再次自动恢复旧账号。
- 每 15 秒及暂停、切章、退后台时先保存本机事件，再发送。已入队的事件不依赖页面存活，切章不等待网络；最后未到检查点的短间隔仍可能因强制终止丢失。
- 图文章节保存后显示“本章已读，待同步”，联网确认后显示完成。同步异常、权限/版本变化明确提示，保留本机记录；操作“重试同步”仍由服务器复验权限。
- 网络恢复、回到前台和定时器推动重试；暂时错误逐步退避，最长 60 秒。同一事件重发使用同一编号和内容，不重复累计学习时长、完成记录或成长奖励。
- 本机待同步的续播位置可恢复；队列按账号、课程、固定版本、章节和营期隔离。退出保留本账号队列，账号注销清除。不会以另一账号代传。

## 3. 关键实现与边界

### F04

`academy-secure-storage` 是本项目自有 UTS 混编模块，使用 [DCloud 官方支持的原生混编方式](https://doc.dcloud.net.cn/uni-app-x/plugin/uts-plugin-hybrid.html)。Android 使用 AndroidKeyStore AES-256-GCM，密文在不参与备份的私有目录，由 AtomicFile 原子提交；iOS 使用设备专属、解锁时可用且不同步 iCloud 的 Keychain 条目。完整 API 地址参与记录隔离和 Android 加密认证。

新会话先写安全存储，再向页面发布。刷新只在明确认证失败时清除本机会话，网络/服务错误保留。所有请求绑定会话代次，涵盖退出后重新登录同一账号，避免只比较用户 ID 留下旧响应竞态。

新增可选 `rotationId`：发刷新前在安全会话中保存，同一编号允许恢复因响应丢失而已生成的新凭证。服务端只保留编号哈希及经过现有领域密钥加密的结果；后续轮换清除旧密文，失效会话不恢复，不同编号重放仍撤销。兼容没有此字段的旧版一次性刷新流程。绝对会话期限不被刷新延长，临近到期时访问期限仍受绝对期限约束。

Web 预览会话和队列仍仅在内存，未把令牌写到 localStorage 来模拟原生持久化。当前构建目标 Android/iOS，不宣称 Harmony 安全存储已交付。

### F07

队列先落盘、确认后再持久删除；若确认丢失或删除失败，重放原事件。队列损坏、写入失败或达到 3000 条上限会提示，不能悄悄清空。400/403/404/409/422 暂停对应事件，保留原因，其他可同步章节仍继续。

补传请求增加 `recordedAt` 和固定 `releaseId`。新客户端按观察时间间隔、每条最多 30 秒计时；首条建立基线，旧事件不回退续播位置。旧客户端和服务端直播心跳保留按实际接收间隔的计时规则。复用 `StudyEvent` 幂等、当前权益/版本/章节开放检查及完成奖励去重。

未来超过一分钟或积压超过 30 天的事件拒绝并保留待处理；此机制不提供防作弊证明，也不开放离线媒体权限。真实 RTC 观看继续由服务端有效观看租约和心跳记录，不把断线时长当直播观看。
