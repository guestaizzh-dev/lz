# M01 大课件上传与音视频播放优化

日期：2026-10-15。对应 C02/C03 本地媒体交付子项，视频音频课件售卖为本轮最高优先级。

## 1. 已解决的问题

- 原后台两个上传入口均限制 100MB，整文件进入内存，60 秒请求超时；上传后只识别文件头即标记可用。
- 新入口支持 **小于 2GiB** 的 MP4、MP3、M4A、WAV；每片 8MiB，逐片落盘并同步、按实际偏移续传。上传中断或刷新后重新选择原文件继续，已传部分保留 7 天。
- 分片重复确认不重复写入；内容不一致、越界、未完成提交、跨上传者访问和权限不足均拒绝。
- 上传完成进入持久处理队列，前台可继续上传其他课件。媒体库/课程编辑共用官方 Pro 上传组件，显示实际进度、暂停、续传、后台处理、失败重试与取消。刷新后可找回未完成任务。
- 只有处理成功的媒体可以进入课程送审/发布，损坏文件和处理中资源不能伪装为可用课件。旧上传接口也进入同一处理流程，私人图片原流程保留。

## 2. 视频和音频处理

视频统一生成 H.264 Main / yuv420p，最高 1080p、30fps，2 秒关键帧间隔，视频峰值码率 4Mbps。音轨统一 AAC、48kHz、128kbps；独立音频也生成 M4A。MP4 索引前置，支持先加载索引并按 Range 请求拖动位置。

处理采用完整解码与转码，保留音视频共享时间轴，补齐缺失时间戳并重采样，不把两个轨道分别清零。输出再次检查实际时长、编码、文件大小与 SHA-256，源文件摘要也保存在媒体处理信息中；不通过则保持不可发布。

一个 API 进程只同时执行一个编码任务，编码使用 2 个线程。处理有持久租约、心跳和重启恢复；旧租约不能覆盖新结果，失去租约会中断编码。失败源文件保留供重试；成功删除源文件，过期任务和残留工作文件按限定路径清理。

两层 Nginx 均为媒体 Range 关闭代理缓冲、关闭压缩；上传采用 9MiB 单请求限制和分片超时，业务 API 不整体放宽为 2GB。播放仍逐次检查课程版本、购课/会员/营期身份和票据，撤权后旧票据不能重新请求媒体。

App 保留原生播放器；音频拖动时独立预览目标位置，避免时间更新把滑块拉回；跳转后过滤旧位置回调，视频增加缓冲状态说明。保留续播、倍速和持久学习队列。

## 3. 课程售卖关联

- 课程编辑只列可用媒体；选择媒体自动带入探测出的实际时长。
- 保存、送审和发布复验媒体状态/类型/私人用途；探测过的媒体不能填报与实际明显不同的章节时长。
- 发布版本、订单授权、购课后学习和退款撤权继续使用既有事务；本批不改写旧发布版本和订单快照。
- 上传处理成功不等于版权/内容审核通过，课程原有独立审核仍需执行。

## 4. 数据与运行配置

第 45 个迁移：`20261015120000_large_media_ingest`，仅新增 `MediaUpload`，不删除旧媒体/订单/学习数据。

字段：`id`、`uploaderId`、`fingerprint`、`name`、`mime`、`bytes`、`receivedBytes`、`state`、`assetId`、`attempts`、`leaseUntil`、`leaseToken`、`failure`、`createdAt`、`updatedAt`、`expiresAt`。上传者/媒体外键、状态/大小/偏移约束、恢复查询索引已配置，通用编辑器不得写这些事实。

运行依赖 FFmpeg / FFprobe。标准 Dockerfile 已安装；本地通过 `FFMPEG_PATH` / `FFPROBE_PATH` 配置，不提交本机工具或真实服务密钥。工具未就绪时上传明确返回服务未就绪。

## 5. 验证证据

- 78 项关联测试通过，覆盖大媒体、课程售卖、直播课程回放、学习与两类营期授权、固定版字幕。
- 真实输入 **235,866,638 字节（约 225MiB）**，有完整图像与音轨，不是填充文件或只有文件头的测试样本；输出约 51.5MiB。
- 实测上传中重启 API 后续传、重复分片、冲突分片、重复完成、过期处理租约恢复、损坏媒体/重试/取消/清理、实际课程发布、Range/HEAD 和撤权均通过。
- 浏览器对处理后的视频跳到 90、15、70、5 秒并继续解码；末次本地浏览器跳转耗时 **36–288ms**，继续播放263帧中0掉帧，具体见 `large-media.json`。输入含有约 179ms 的刻意音轨偏移，输出保留该偏移（AAC 帧量化带来约一帧差异），末尾偏移也保持，没有引入持续累积的漂移。
- 官方Pro实际页面8项通过：真实管理员登录、大文件暂停/继续、后台处理不阻塞下次上传、刷新找回任务、媒体可用/实际时长、课程共用入口、损坏媒体失败提示和刷新后重试/取消，0个页面运行异常。
- API、官方 Pro 生产构建与 App Android 蒸汽资源/Web 导出通过。
- 证据目录：[outputs/large-media-2026-10-15](../outputs/large-media-2026-10-15/)，包含数据库/HTTP 测试日志、真实页面操作、截图和性能指标；公网大文件见 `online-large-upload.json`，取消清理见 `online-upload-cleanup.json`。所有本地业务测试在独立临时库执行。

## 6. 交付边界

后端及后台已部署 **20261015-large-media-01**，45个迁移已应用；备份数据库/媒体校验通过，21类原业务数据摘要保持，614个发行文件哈希复验通过。公网8项HTTP检查和生产镜像内实际编码检查通过。公网随后实际上传完整235,866,638字节视频，耗时27,036ms，经过两层真实代理；校验接收字节数后取消诊断任务，服务端再次核查源文件已删除，未创建课程、订单或可售媒体。原有测试数据保持。

公网验证发现并修复两层Nginx上传集合地址被自动补斜杠、POST转GET的问题；集合/子路径现在统一直达API，超限请求正确返回400，不产生错误任务。

当前代码支持大文件分片与本地处理，不等于已完成 C02/C03 的 COS/VOD/CDN 商用验收。

初查生产磁盘只剩约2.8GB。编码工具镜像准备后降至约1.6GB；核查全部容器和回退版本后，仅清理本项目8个未使用的早期镜像，保留当前、回退和近期发行，最终可用约 **4.8GB**。未删除数据库、媒体卷或其他项目资源。代码会在创建/处理任务前检查空间，容量不足时明确拒绝；频繁上传大课件仍须扩容媒体存储或提供正式对象存储。任务上限为每个运营账号 3 个未完成任务，处理队列串行，避免编码抢占过多服务资源。

本轮未生成新APK、未更新手机安装；没有手机/iOS 真实播放、长时间弱网和公网大并发验收，不能承诺任意设备和网络“永不卡顿”。处理能避免常见编码/关键帧/时间戳引起的问题；源素材本身口型不一致需要重新校正源素材。原 C02/C03/C12/CO02/CO03/CO13 商用需求保持未验收，商用基线不变。
