# 会员M09：R1积分兑换课程优惠券收尾

日期：北京时间2026-10-18。复用已有R2积分兑换、营销券包和课程订单；没有另建兑换或券账本。内部实现与正式商用验收分开记录。

## 1. 操作和规则

1. 后台营销中心新建优惠券，选择「积分商城兑换」，设置优惠金额/折扣、门槛、课程范围、北京时间期限、发行量、每人总限领和Android允许支付渠道。发布后不能把发放方式改为另一种；需要调整条款应另建模板。原券快照不改。
2. 积分商城维护兑换规则，选择该积分专用券，设置所需积分、库存和每日限额。普通公开免费券不允许成为扣分兑换目标；暂停模板/兑换任一入口即停止新兑换，已有券按原条款使用。
3. 学员确认条款后兑换。同事务锁住用户、兑换规则、积分账户与模板：核对可用积分/待抵扣、两层库存及限额，扣分和发券同时提交。中断回滚；结果未知用原编号/原参数重试，不重复扣分发券。100积分兑换已用实际测试覆盖，积分成本仍由运营规则配置。
4. 兑换记录「查看我的优惠券」直接打开本人券包；显示可用、已占用、已使用/过期状态。Android课程原确认页自动择优、一单一券，下单冻结，可信付款核销，取消或成功退款按原有效期返券。iOS数字课程仍用已有合法商店产品，不应用外部券价格。

**本次发现并修复的缺口**：原积分兑换用券也能从公开领券接口免费领，绕过扣分。新增claimPolicy明确PUBLIC/POINTS，公开列表排除积分券，公开接口即便猜中ID/复用请求编号也拒绝积分券。积分发券只从兑换事务内部调用，用户请求不能自行指定来源。

另外修正后台「适用全部课程」未选择时提交空字符串的问题，改成空数组；App展示券门槛/截止、真实剩余库存及已达限领原因，兑换完成可直达券包，积分/券包登录回跳保留。个人限额查询批量聚合，避免每条规则重复查询本人次数。
