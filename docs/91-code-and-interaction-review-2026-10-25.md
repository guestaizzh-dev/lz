# 视频课程售卖、观看与直播链路 Review（2026-10-25）

范围：付费视频/音频课件从报价、下单、支付确认到学习播放，以及管理员直播从准备开播、服务端录制到回放的链路。只改与确认问题直接相关的代码，未改业务规则、价格、退款条件或页面结构。验证为本地构建与隔离数据库测试，不是手机、真实渠道或线上验收。

## 链路与入口（现状）

| 链路 | 入口与状态流转 | 依赖 |
| --- | --- | --- |
| 课程报价与下单 | 课程详情 `course/detail` → `course/purchase`；`SaleOffer` 整数分报价加发布版本快照；`quoteHash` 冻结价格、版本与优惠选择；`TradeOrder` 以 `requestKey` 幂等，价格或版本漂移返回 409 | `commerce/courses/:id/quote`、`commerce/course-orders`、会员价/券/拼团/公益择优 |
| 支付与授权 | 待支付订单 15 分钟；`payment` 只接受服务端验签/查单结果；`confirmPayment` 同事务写收款、账本与 `Enrollment`；客户端“已付款”不授权 | 微信/支付宝适配、OutboxJob 恢复、退款冻结 |
| 购买后观看 | `course/player`：`learning/courses/:id` 决定可学章节，`learning/lessons/:id/media` 发放短时媒体票据（含退款/停交付校验），进度按 15 秒批量写 `StudyProgress` | 媒体票据续签、学习队列、离线下载 |
| 直播 | 后台预告 → 会员 `live/detail` 预约/进入 → `live/watch` 领取 RTC 租约、20 秒心跳、评论/连麦；管理员开播台 `ENTER` 触发 PREPARE、录制任务与单场直播约束；结束由服务端录制进程出片，审核后 `REPLAY_READY` | ZEGO RTC、`LiveRecordings`、后台开播台 |

## 已确认并修复

| # | 问题 | 修复 | 原因 |
| --- | --- | --- | --- |
| 1 | 管理员直播有三个“准备开播”入口：后台开播台 `ENTER` 有单场约束并创建录制任务，后台场次管理 `admin/live/sessions/:id/state` 与老师/管理员 App `live/sessions/:id/host-state` 没有，可同时准备两场且被跳过的一场永远没有回放 | `LiveService.state` 对管理员直播的 PREPARE 使用同一把咨询锁与单场检查，并在事务成功后 `recordings.ensure` | 同一业务动作不能因入口不同产生两种状态机；回放是直播交付的一部分 |
| 2 | `live/rtc/refresh` 在观看时长记账失败时整次心跳报错，观众被当成断线 | 观看时长为尽力而为，进度写入失败只记录不影响心跳 | 心跳只负责准入与令牌续期，辅助记账不能踢人 |
| 3 | 取消后仍完成的录制会生成 `PENDING` 回放，但任何接口都不能审核/发布它 | 已取消场次保留私有录像资产，不再创建无法处理的回放行 | 避免后台出现永远处理不了的待办 |
| 4 | `quoteHash` 含直播场次的 `state/version`；结算页打开后场次开播/结束/回调都会让购买返回“价格或课程版本已更新”，实际价格未变 | 报价快照与哈希只保留场次的 `id/title/scheduledAt`；是否可售仍由 `deliverable` 在校验时判断 | 哈希应只覆盖用户确认的成交条件，状态抖动不是价格变化 |
| 5 | App 直播列表把主推场次又在下方列表重复渲染一次 | 列表排除已作为头图的主推场次，空状态仍按全部数据判断 | 同一入口不重复出现同一场直播 |
| 6 | 已过开播时间但仍为 `SCHEDULED` 的场次显示“直播预告”和“预约本场” | 过期未开播显示“等待开播”与说明；未预约时不再显示预约按钮，已预约的仍可取消；本地时钟 30 秒刷新标签 | 预约提醒只对未开始的场次有意义，状态文案要与时间一致 |
| 7 | 课程学习页刷新时整页被加载态替换，错误态与已加载内容同时出现 | 只在尚未加载到课程时显示加载态，错误仍始终提示；视频高度按屏幕宽度 9:16 计算（200–420px） | 减少返回页面时的布局跳动，并适配平板/网页宽度 |
| 8 | 切换支付渠道或拼团方式后重试下单可能一直返回“下单标识已用于其他操作” | 用户主动刷新报价时轮换 `requestKey` | 渠道参与 requestHash，旧标识不能复用；待支付订单仍由服务端阻止重复下单 |
| 9 | 从登录页返回但未登录时，观看页停在“正在连接直播”且无提示 | 第二次进入时提示“登录后可观看本场直播”并可重试 | 未登录是明确状态，不能伪装成连接中 |

## 验证

- API 构建通过；隔离临时数据库全量测试 **835/835 通过**、0 失败、0 跳过，耗时 523 秒，日志 `outputs/review-2026-10-25/api-full-tests.log`。
- `live-broadcasts` 新增两项断言：场次入口的单场约束与录制任务、取消场次不生成不可发布回放；连同既有直播/课程/学习/退款场景全部通过。
- 测试临时目录需指向工作区内：默认 `D:\Temp` 下 FFmpeg 写入被本机系统拒绝，属环境限制而非代码失败；首次 3 项失败均由该原因引起。
- App Web 导出（HBuilderX 5.26）与 Android 蒸汽模式字节码编译均覆盖 76 页面且无编译错误，仍有既有的 `<button>` 子元素与 `aria-hidden` 警告；未打包 APK、未接手机。证据：`outputs/review-2026-10-25/mobile-web-build-final.log`、`outputs/review-2026-10-25/mobile-android-compile-final.log`。
- 未验证：真实微信/支付宝/Apple 收款与退款、真机播放与直播、ZEGO 公网推流/录制、弱网与长时稳定性。以上仍按 [26](26-remaining-development-plan.md) 与 [83](83-status-and-gaps-2026-10-19.md) 的验收口径。

## 发现但未改（需业务决定或超出本次范围）

- 退款进行中的准入规则三处不一致：直播按订单级 `APPROVED/REFUNDING` 拒绝，视频按当前收款笔加 `FAILED` 拒绝，版本调整按 `REQUESTED/APPROVED/REFUNDING` 且限退课原因。重复支付异常退款可能误伤已购直播；需统一规则后再改。
- 学习进度接口本身不复查退款冻结（播放与图文读取已复查），仅影响退款处理期间的完成/成长记录。
- `paymentStatus` 已由接口返回但 App 只显示通用“查询订单状态”，渠道返回 `USERPAYING/PAYERROR` 时没有更具体的原因文案。
- 直播过期 RTC 租约的清扫没有尝试次数上限，失败会持续重试；需要迁移与容量验证。
- `<button>` 内含 `<text>` 的原生警告覆盖多页，需真机确认文字是否被裁掉后再统一改造。
