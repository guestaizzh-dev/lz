# 桌面端响应式与视觉一致性（2026-10-25 第 2 轮）

本轮针对“整体优化”目标做系统检查后的第一批改进，范围是 App Web 构建在宽窗口下的版式、交互反馈一致性和键盘可达性。没有改业务规则、导航、配色与字体。

## 本轮评估的不足

1. App 是移动优先布局，Web 构建在 1366/1440 窗口下所有卡片、封面、阅读正文都被拉到几乎满宽，行宽过长；页头返回键、底部操作栏与内容左缘对不齐。
2. Web 构建没有统一的键盘焦点样式，Tab 键看不到当前位置；原样式只在个别组件内零散定义。
3. 直播列表在已有数据时刷新失败，会把整页替换成“暂时无法打开”，已加载的场次消失；同一产品的直播详情页已有更轻量的顶部提示，两处不一致。

## 改动

| 位置 | 改动 |
| --- | --- |
| `apps/mobile/styles/app.css`（Web 条件编译） | `.content` 固定为 100% 宽、上限 720px 并水平居中；页头与底部操作栏用对称内边距对齐同一列；为主按钮、次按钮、文字按钮、重试、圆标操作、评分与筛选补充统一的金色 `:focus-visible` 外框 |
| `apps/mobile/lib/presentation.ts` | `viewWidth()` 在 Web 上限 688px（720 减去内容左右内边距），与 `ArtImage`、封面、视频高度等按内容宽度计算的元素一致；App 原生不受影响 |
| `apps/mobile/pages/live/index.uvue` | 已有场次时刷新失败改为顶部轻量提示与“重新加载”，不再清空列表；列表为空时仍显示完整错误/加载态 |

## 验证

- HBuilderX 5.26 Web 导出成功，76 页面；产出 CSS 内含 `max-width:720px`、`calc((100% - 720px) / 2)` 与焦点规则，脚本内含 `Math.min(688, …)`。
- Android 蒸汽模式字节码编译 76 页面，无编译错误（既有 `<button>` 子元素与 `aria-hidden` 警告不变）。
- 真实浏览器截图（Edge 无头，静态服务本地 Web 产物）：
  - 1440×1000：首页、学堂、直播、好物、登录、课程学习页内容列居中，页头返回键与列左缘对齐，底部主操作与列同宽。
  - 390px：用同源 iframe 固定视口截取首页与直播页，元素无横向溢出，导航 7 项与底部 5 项完整，与移动端原布局一致（Windows 无头窗口小于约 500px 会钳制，直接 `--window-size=390` 的截图不可作为依据）。
  - 证据目录：`outputs/review-2026-10-25/shots/`。
- 本地预览直连生产 API 会被跨域拦截，截图只能覆盖加载/空/错误状态与版式，不能代表有数据卡片的最终视觉；数据页仍以构建、代码与既有线上只读取证为准。

## 下一轮候选

- 在可用的同源代理或本地数据下复核有数据的列表、购课页与播放页在 1440/1024/768 三档的视觉。
- 底部原生 tabBar 在宽窗口仍等分整屏，属框架自带结构；若要收窄需在 Web 侧覆盖框架样式，先确认不影响移动端。
- 退款准入规则三处不一致与直播租约清扫重试上限（见 [91](91-code-and-interaction-review-2026-10-25.md)）。
